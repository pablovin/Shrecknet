# Architect Step 2: Entity Generation API

This document describes how to use the Architect Step 2 API for generating and updating entities from validated proposals.

## Overview

The Architect pipeline has two steps:

1. **Step 1 (Analysis)**: Analyze text and propose entities to create/update
2. **Step 2 (Generation)**: Generate/update entities based on validated proposals

## Step 1: Request Analysis

Use the existing endpoint to analyze an ontology instance:

```http
POST /api/jobs/architect/{agent_id}/analyze
Content-Type: application/json

{
  "ontology_instance_id": "instance-123",
  "ontology_id": 42,
  "max_chunks": 50,
  "chunk_size": 1200
}
```

**Response:**
```json
{
  "id": "run-uuid",
  "agent_id": "agent-123",
  "ontology_id": 42,
  "ontology_instance_id": "instance-123",
  "status": "pending",
  "proposals": [],
  ...
}
```

## Step 2: Validate and Generate

### 2.1 Get Proposals

Retrieve the run with proposals:

```http
GET /api/jobs/architect/runs/{run_id}
```

**Response:**
```json
{
  "id": "run-uuid",
  "status": "completed",
  "proposals": [
    {
      "id": "proposal-1",
      "proposal_type": "new_instance",
      "entity_definition_id": 5,
      "alias": "John Smith",
      "confidence": 0.85,
      "justification": "Character mentioned in chapter 3",
      "chunks": ["John Smith arrived at the castle...", "..."],
      "status": "pending"
    },
    {
      "id": "proposal-2",
      "proposal_type": "update_instance",
      "entity_instance_id": "existing-entity-123",
      "entity_definition_id": 5,
      "alias": "Alice",
      "confidence": 0.92,
      "chunks": ["Alice greeted John..."],
      "status": "pending"
    }
  ]
}
```

### 2.2 Submit Validated Proposals

After reviewing proposals on the client side, submit the validated list:

```http
POST /api/jobs/architect/runs/{run_id}/generate
Content-Type: application/json

{
  "run_id": "run-uuid",
  "author_type": "user",
  "author_id": "user-123",
  "validated_proposals": [
    {
      "proposal_id": "proposal-1",
      "status": "approved",
      "corrected_alias": "John Smith",
      "corrected_entity_definition_id": null,
      "merged_into_proposal_id": null
    },
    {
      "proposal_id": "proposal-2",
      "status": "approved"
    },
    {
      "proposal_id": "proposal-3",
      "status": "rejected"
    },
    {
      "proposal_id": "proposal-4",
      "status": "merged",
      "merged_into_proposal_id": "proposal-1"
    }
  ]
}
```

**Response:**
```json
{
  "status": "accepted",
  "task_id": "celery-task-id",
  "run_id": "run-uuid",
  "message": "Entity generation task started"
}
```

## Proposal Statuses

- `pending`: Initial state after step 1 analysis
- `approved`: User approved the proposal for entity creation/update
- `rejected`: User rejected the proposal
- `merged`: Proposal was merged into another proposal (specify `merged_into_proposal_id`)

## Validation Rules

1. **Approved proposals**: Will create new entities or update existing ones
2. **Merged proposals**: Only the main proposal (the one being merged into) will be processed
3. **Rejected proposals**: Will be ignored
4. **Corrected data**: 
   - `corrected_alias`: Override the suggested alias
   - `corrected_entity_definition_id`: Change the entity type
   - `merged_into_proposal_id`: Merge this proposal into another

## Entity Generation Process

For **new entities** (proposal_type = "new_instance"):
1. Extract auto-generatable properties from text chunks
2. Extract auto-generatable relationships to other entities
3. Generate a concise autogenerated_text summary
4. Create the entity in the graph database

For **update entities** (proposal_type = "update_instance"):
1. Load existing entity data
2. Extract new properties/relationships not already present
3. Update the autogenerated_text summary with new information
4. Update the entity in the graph database

## Background Job Tracking

The generation process runs asynchronously. Track progress via:

```http
GET /api/jobs/background/{job_id}
```

The job details will include:
- `created_entity_ids`: List of newly created entity instance IDs
- `updated_entity_ids`: List of updated entity instance IDs

## Retrieving Generated Entities

After generation completes, fetch the generated entities:

```http
GET /api/jobs/architect/runs/{run_id}
```

Each approved proposal will have a `generated_entity_instance_id` populated.

You can then fetch the full entity data from the ontology instance:

```http
GET /api/ontology/instances/{instance_id}
```

## Example Workflow

1. **Start Analysis**:
   ```
   POST /api/jobs/architect/{agent_id}/analyze
   → Returns run_id
   ```

2. **Wait for Completion**:
   ```
   Poll GET /api/jobs/architect/runs/{run_id}
   → Until status = "completed"
   ```

3. **Review Proposals**:
   - Display proposals to user
   - User approves, rejects, or merges proposals
   - User may correct aliases or entity types

4. **Submit Validated Proposals**:
   ```
   POST /api/jobs/architect/runs/{run_id}/generate
   → Returns task_id
   ```

5. **Track Generation**:
   ```
   Poll GET /api/jobs/background/{job_id}
   → Until status = "done"
   ```

6. **Fetch Results**:
   ```
   GET /api/jobs/architect/runs/{run_id}
   → Check generated_entity_instance_id on proposals
   
   GET /api/ontology/instances/{instance_id}
   → View the updated instance with new/updated entities
   ```

## Notes

- Only entities with `auto_generatable=true` on their properties/relationships will have those extracted
- Relationships are only created if both source and target entities exist
- The system will not invent information - it only extracts what's explicitly present in the text
- Parallelization is used to speed up processing of multiple entities
