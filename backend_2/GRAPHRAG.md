# GraphRAG Module

Semantic retrieval-augmented generation (RAG) over Neo4j for Shrecknet.

## Overview

The GraphRAG module provides:
- **Multilingual embeddings** using `paraphrase-multilingual-MiniLM-L12-v2` (384-dim)
- **Per-ontology embedding** for compartmentalized, fast querying
- **Semantic search** with KNN + neighborhood expansion
- **Lightning-fast retrieval** optimized for chat interfaces
- **REST API endpoints** for embedding creation and querying

## Architecture

### Modules

- `app/graphrag/embedding_service.py` - Context text building and embedding generation
- `app/graphrag/retrieval_service.py` - Semantic search and context assembly
- `app/api/routers/graphrag.py` - REST API endpoints
- `app/schemas/graphrag.py` - Pydantic schemas for requests/responses

### Data Model

Each `EntityInstance` node in Neo4j gets:
- `context_text` (string) - Formatted context for embedding
- `text_embedding` (float[384]) - Multilingual embedding vector
- `text_embedding_model` (string) - Model identifier
- `text_embedding_dim` (int) - Embedding dimensionality

Vector index: `entity_text_vec_idx` on `text_embedding` with cosine similarity.

## API Endpoints

### Authentication
- Embedding operations require `admin` or `world_builder` role
- Search operations are open to all authenticated users

### POST /graphrag/index/ensure
Create Neo4j vector index if it doesn't exist.

**Requires**: admin or world_builder

**Response**:
```json
{
  "index_name": "entity_text_vec_idx",
  "exists": true,
  "embedding_model": "sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2",
  "embedding_dim": 384
}
```

### POST /graphrag/embed/node
Embed a single node by ID.

**Requires**: admin or world_builder

**Request**:
```json
{
  "node_id": "entity-uuid-123",
  "ontology_id": 1
}
```

**Response**:
```json
{
  "node_id": "entity-uuid-123",
  "context_text": "Name: Lodin\nLabels: Character, Vampire\n...",
  "embedding_model": "sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2",
  "embedding_dim": 384
}
```

### POST /graphrag/embed/ontology
Embed all nodes in an ontology (batch operation).

**Requires**: admin or world_builder

**Request**:
```json
{
  "ontology_id": 1,
  "batch_size": 50
}
```

**Response**:
```json
{
  "ontology_id": 1,
  "nodes_processed": 245,
  "nodes_failed": 2
}
```

**Note**: This may take several minutes for large ontologies. Process runs in batches to manage memory.

### POST /graphrag/search
Perform semantic search over embedded nodes.

**Request**:
```json
{
  "query": "Who is the Prince of Chicago?",
  "ontology_id": 1,
  "k": 10,
  "score_threshold": 0.5,
  "include_neighbors": true,
  "neighbor_limit": 10
}
```

**Response**:
```json
{
  "query": "Who is the Prince of Chicago?",
  "results": [
    {
      "node_id": "entity-uuid-123",
      "name": "Lodin",
      "labels": ["Character", "Vampire"],
      "score": 0.92,
      "context_text": "Name: Lodin\nLabels: ...",
      "text": "Original text...",
      "autogenerated_text": "Generated summary...",
      "ontology_id": 1,
      "neighbors": [
        {
          "rel_type": "RESIDES_IN",
          "node_id": "entity-uuid-456",
          "name": "Chicago",
          "label": "City"
        }
      ]
    }
  ],
  "total": 1,
  "ontology_id": 1
}
```

### POST /graphrag/context
Get formatted context for LLM from semantic search.

**Request**:
```json
{
  "query": "Tell me about the Camarilla",
  "ontology_id": 1,
  "k": 5,
  "score_threshold": 0.5
}
```

**Response**:
```json
{
  "query": "Tell me about the Camarilla",
  "context": "Query: Tell me about the Camarilla\n\nRelevant Information:\n\n1. Camarilla (Score: 0.95)\nName: Camarilla\nLabels: Faction\n...",
  "ontology_id": 1
}
```

## Context Text Format

Context text is built from each node using:

```
Name: {name}
Labels: {labels_csv}
Ontology: {breadcrumb_path}
Properties: {key=value; key=value}
Relations: {rel_type -> target_name (target_label)}
Summary: {summary_text}
```

Example:
```
Name: Lodin
Labels: Character, Vampire
Ontology: Entity > Person > Vampire > Camarilla
Properties: clan=Toreador; generation=10th
Relations: resides_in -> Chicago (City); member_of -> Camarilla (Faction)
Summary: Prince of Chicago, Toreador clan, 10th generation.
```

## Embedding Model

**Model**: `paraphrase-multilingual-MiniLM-L12-v2`
- **Dimensions**: 384
- **Language Support**: 50+ languages
- **Speed**: Fast inference on CPU
- **Quality**: Good balance for chat interfaces

The model is cached globally for performance. On first use, it downloads ~120MB.

## Performance Optimization

### Per-Ontology Embeddings
- Embeddings are scoped by `ontology_id`
- Search can filter to specific ontology for faster results
- Re-embedding affects only changed ontology

### Batch Processing
- `embed_ontology` processes nodes in configurable batches (default 50)
- Reduces memory footprint and network round-trips
- Errors in individual nodes don't block the batch

### Retrieval Speed
- Vector index provides O(log n) KNN search
- Neighbor expansion limited to configurable count (default 10)
- Results cached in formatted context for LLM

## Workflow

### Initial Setup
1. **Create vector index**: `POST /graphrag/index/ensure`
2. **Embed an ontology**: `POST /graphrag/embed/ontology` with `ontology_id`
3. Wait for batch processing to complete

### Usage
1. **Search**: `POST /graphrag/search` with query and optional filters
2. **Get context**: `POST /graphrag/context` for formatted LLM input

### Maintenance
When content changes:
- **Single node**: `POST /graphrag/embed/node` with `node_id`
- **Ontology batch**: `POST /graphrag/embed/ontology` with `ontology_id`

Re-embedding is fast enough for real-time updates (< 1s for single nodes).
