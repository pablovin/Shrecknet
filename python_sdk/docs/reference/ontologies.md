# OntologiesAPI

Ontology CRUD and world stats endpoints.

## Methods

### `create(self)`

Create ontology.

### `list(self)`

List ontologies with optional filters and pagination.

### `get(self, ontology_id)`

Fetch ontology by id.

### `update(self, ontology_id, **fields)`

Patch ontology fields.

### `delete(self, ontology_id)`

Delete ontology by id.

### `world_stats(self)`

Return world stats for one or multiple ontologies.

### Atlas discovery

- `scene_sources(ontology_id, *, skip=0, limit=10) -> AtlasSourcePage`: distinct provenance pages with titles, artwork, scene counts, and `has_more`. Increment `skip` by the returned result count. Limit is 1–100.
- `folio_detail(ontology_id, page_id) -> AtlasFolioDetail`: bounded Living Folio page content. `page_id` is the ontology-instance page ID, not an entity-instance ID. The `folio_projection` marker reports that scene bodies and relationship collections were omitted; use the dedicated reads below.
- `folio_authors(ontology_id, page_id) -> list[AtlasAuthor]`: distinct public author summaries for a page.
- `folio_relationships(ontology_id, page_id, *, entity_id=None, query=None, group=None, skip=0, limit=30) -> AtlasRelationshipPage`: bounded relationship rows and group counts, with direction and separate entity/page target IDs. Limit is 1–100.
- `scenes(ontology_id, *, query=None, related_entity_id=None, source_entity_id=None, has_perspectives=False, related_only=False, skip=0, limit=30) -> AtlasScenePage`: scene name/description search before pagination, with exact-source or related-entity filters. `related_only=True` requires `related_entity_id` and excludes provenance edges. Each row distinguishes its owning instance from its nullable provenance `source_page`. Counts exclude private perspectives except for admins.
- `scene_source(ontology_id, scene_id) -> AtlasSourceReference`: canonical provenance page for an evidence link; no fallback to the scene's owning container.
- `elders(ontology_id, *, skip=0, limit=100) -> list[AtlasElderCard]`: active world-assigned Elder portraits in newest-first service order. Fetch the next page only when the returned page is full.

All operations require authenticated world graph access. See the [backend Living Folio contract](../../../Documentation/API/SCENE_GRAPH_API.md#living-folio-page-reads) for page projections, authorization, empty/error behavior, and rollout requirements. These models are available from `shrecknet_client.atlas`.

Example: [read a Living Folio page](../../examples/02_ontology_management/03_read_living_folio.py).

World graph and discovery reads are available to every authenticated role, including players without entity assignments. Private perspectives remain restricted to administrators. See [Scene Graph API](../../../Documentation/API/SCENE_GRAPH_API.md) for the authorization contract.


### Admin inline updates

`patch_folio(ontology_id, page_id, patch: AtlasFolioPatch) -> AtlasFolioDetail`
updates only supplied fields. Import `AtlasFolioPatch` from `shrecknet_client.atlas`.
Pass `expected_updated_at=detail.updated_at` and the selected `entity_instance_id`.
Use `name`, `node_avatar_url`, `text`, `autogenerated_text`, `properties`, and/or
`relationships`; explicit null clears artwork or generated text. Collections replace
the selected entity's collection. HTTP 409 means another edit changed the page;
reload and reconcile before retrying. Admin authorization is enforced upstream.
See the [API contract](../../../Documentation/API/SCENE_GRAPH_API.md#admin-partial-folio-updates)
and [editing example](../../examples/02_ontology_management/04_edit_living_folio.py).


`AtlasFolioPatch.relationship_changes` accepts `AtlasRelationshipChanges(add=[...],
remove=[...])` from `shrecknet_client.atlas`. Additions use the existing
`AtlasFolioRelationshipInput` with explicit target entity IDs; removals use the
relationship row's durable `relationship_instance_id`. Do not send a replacement
`relationships` array at the same time. Check `folio_projection.relationship_editing`
for `delta-v1`; older services omit it. Historical rows without durable IDs cannot
be removed through this contract. Retarget/type changes remove the selected edge
and add a replacement carrying its metadata; unchanged edges retain their identity.
See the backend targeted Folio contract for limits, atomicity, and rollback behavior.


### Create a Folio page

`create_folio(ontology_id, payload: AtlasFolioCreate) -> AtlasFolioDetail` creates
one page as the current administrator. Supply `request_id` (UUID), `definition_id`
and `name`; optional narrative, cover, property and relationship fields follow the
backend contract. Authors/aliases/identities are assigned upstream. Keep the same
request ID and immutable content when retrying an uncertain response; changed
content under an already-committed key returns 409.

`find_folio_creation(ontology_id, request_id) -> AtlasFolioDetail | None` recovers a
confirmed page scoped to the current admin and world, returning None only for 404.
Other errors are propagated. Historical legacy POST permissions are unchanged.
Deploy the backend and `atlas_creation_request_unique` constraint before using
these methods. See [the API contract](../../../Documentation/API/SCENE_GRAPH_API.md#admin-folio-page-creation)
and [creation example](../../examples/02_ontology_management/05_create_folio_page.py).
