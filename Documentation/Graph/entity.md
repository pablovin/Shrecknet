# Entity Node (`EntityInstance`)

In v0.3, entities remain essential but no longer carry timeline priority.

## Purpose

`EntityInstance` represents stable world objects and actors:

- Characters
- Places
- Organizations
- Artifacts
- Any ontology-defined domain object

## Core Entity Properties

Typical fields include:

- `entity_instance_id` (unique identifier)
- `instance_id`, `ontology_id`
- `entity_definition_id` (ontology entity definition)
- `alias`
- `text`, `autogenerated_text`
- `properties` (ontology-defined values)
- metadata: `author_type`, `author_id`, `created_date`, `last_updated_date`
- embedding fields for retrieval

## Entity Relationships

Entity-to-entity edges remain valid for structural world modeling:

- `(EntityInstance)-[:RELATES_TO]->(EntityInstance)`

These come from ontology relationship definitions.

## Entity in Event-Centric Memory

Entities are connected to events through participation edges:

- Source role:
  - `(Event)-[:SOURCE_ENTITY]->(EntityInstance)`
- Involvement role:
  - `(Event)-[:INVOLVES_ENTITY]->(EntityInstance)`

This allows entities to stay reusable and stable while event chains handle chronology.

## Practical interpretation

- Entities answer: **what/who exists**.
- Events answer: **what happened and in which order**.
