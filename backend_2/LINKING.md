Ontology Instance Auto-Linking

Overview
- Background job `ontology.link_instance` parses each entity’s `text` and `autogenerated_text` and decorates mentions of other entities in the same ontology instance.
- Mentions match either entire aliases or their word tokens (length >= 3), case-insensitive. This provides simple similarity so “Professor Nevada Jones” links to the entity with alias “Nevada”.
- The job runs whenever an ontology instance is created or updated. When entities are added/edited, the job scans all entities in that instance efficiently with one fetch and one bulk update.
- The decorated HTML is written to both `e.text` and `e.text_linked` so UIs can read from `text` directly.

HTML Decoration
- Each detected mention becomes an anchor element with data attributes so the frontend can resolve/display details without hardcoding URLs.
- Example: if instance_id is 123 and a reference to alias “Nevada” points to entity id `e-456`:
- `<a data-ontology-instance="123" data-entity-id="e-456" data-entity-alias="nevada">Nevada</a>`
- Attributes:
  - `data-ontology-instance`: the ontology instance id
  - `data-entity-id`: the target entity instance id
  - `data-entity-alias`: the matched alias (lowercased)

Triggering
- Create instance: immediately triggers `ontology.link_instance` for the new instance.
- Update instance: triggers after updating nodes, so new entities get referenced across existing texts.

Performance Notes
- The job reads all entities for the instance once, builds a compact regex of unique aliases and tokens (sorted longest-first), and performs a single UNWIND bulk update.
- Tokenization adds only tokens of length >= 3 to avoid noisy matches.
- A fuzzy fallback (edit distance ≤ 1) is used only when no exact matches were found in a text, to keep performance predictable.

Limitations
- Matching uses exact token equality (case-insensitive) and alias equality; no heavy fuzzy matching to keep the job fast on large graphs.
- Self-links are suppressed; an entity will not link to itself.

Extensibility
- To support richer similarity (e.g., Levenshtein), extend `app/utils/linker.py` to generate candidate variants and expand the alias map.
